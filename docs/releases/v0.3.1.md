# nwt-substrate v0.3.1 — the transparency + sensitivity patch

> **Released 2026-05-28.** The first independent reproduction of the v0.3.0 benchmark suite (Pasquale Kaboth, on the d12rg list) asked the right question: *how sensitive are the predictions to small changes in the structural identities?* Answering it produced a new tool — `nwt_substrate.sensitivity` — and, in the course of building it, surfaced two predictions that were reporting **measured inputs or overstated accuracies** rather than honest forward predictions. Both are now fixed in the open. This is a total-transparency patch: the headline `sin²θ_W` number gets **worse** (from a claimed 0.06 % / hidden 43 ppm to an honest 3.5 %), because that is the truth.

## The story

A reader reproduced all 38 benchmarks on independent hardware, confirmed the suite, and flagged that some predictions (the Z-boson width, the muon lifetime) deviate much more than the headlines — then asked whether perturbing the structural identities would distinguish *robust consequences of the structure* from *coincidences of specific couplings*.

That is a look-elsewhere question, and it deserved an operational answer. Building one exposed a deeper issue: several headline predictions re-encoded the substrate's structural integers as **bare literals** in the shim formulas instead of importing the asserted ISA constants — so a perturbation to the ISA did not actually propagate into them. And one prediction, `sin²θ_W`, was not computing the substrate formula at all: it was reporting the **measured** effective angle as if it were the forward prediction.

## 1. The sensitivity sweep

`nwt_substrate.sensitivity` perturbs each leaf integer constant in `isa/constants.py` by ±1, re-imports the whole library in a fresh `python -O` subprocess (`-O` strips the import-time structural-identity `assert`s so the deliberately-inconsistent ISA still loads), recomputes every benchmark, and records which predictions move:

```bash
python -m nwt_substrate.sensitivity
```

```python
import nwt_substrate.sensitivity as sens
report = sens.integer_sweep()
report.movers("DIM_S_SPIN7")   # benchmarks that move when the octonion dim (8) moves
report.inert_integers          # integers that move no prediction
report.never_moved             # predictions not coupled to any structural integer
report.coupling()              # benchmark -> how many distinct integers move it
```

The output is a robustness map. An integer that moves many independent observables at once (`DIM_S_SPIN7` moves 13) cannot be a per-observable tuning knob — that is the anti-look-elsewhere evidence. Integers that move nothing, and predictions that move under nothing, are flagged honestly.

The tool transiently rewrites the source of `isa/constants.py` and always restores it (in-memory original + `finally`); it requires a writable / editable install.

## 2. Wiring predictions to the ISA

The sweep showed that 21 of 38 predictions were decoupled from the structural integers in code. The clean, **value-preserving** cases are now wired through `isa`:

- `electroweak/substrate_gf.py`: `25 → H_V_SO7**2`, `625 → H_V_SO7**4` (q_cinq = 5 = h_v(so7), matching the cosmology `omega_b_c` convention).
- `electroweak/substrate_ckm.py`: imports `N_VERTICES_K7` and `DIM_ADJ_SPIN7` from `isa` instead of redefining them locally.

Every predicted value is byte-identical; the only change is that a structural-integer perturbation now propagates. Predictions coupled to the ISA rose **17/38 → 21/38** — `benchmark_fermi_constant`, `benchmark_higgs_vev`, and `benchmark_full_ckm` are now load-bearing.

## 3. The `sin²θ_W` correction (the important one)

The substrate forward prediction is

```
sin²θ_W = (2 + α) / (DIM_OCTONION + 1) = (2 + α)/9 = 0.22303
```

which is **~3.5 % from PDG 0.23122** — a leading-order result. Earlier suite versions reported the hardcoded **measured** effective angle `SIN2_THETA_W = 0.23121` (~43 ppm) in the `sin²θ_W` benchmark, and the docs variously claimed "0.06 %" (from a spurious `0.23139`) or "43 ppm". None of those was the substrate prediction.

This release:

- adds `electroweak.constants.SIN2_THETA_W_SUBSTRATE = (2 + α)/(DIM_OCTONION + 1)`, sourced from the ISA;
- keeps `SIN2_THETA_W = 0.23121`, now **explicitly labeled** as the measured Z-pole coupling input (the absolute Z observables need the effective angle — `Γ_Z` and the rest are unchanged), **not** a prediction;
- makes `benchmark_sin2_theta_W` report `(2 + α)/9 = 0.22303` at its true 3.5 %;
- corrects the accuracy claim across `README.md`, `llms.txt`, `llms-full.txt`, `docs/index.md`, `docs/FAQ.md`, `docs/shims/electroweak.md`, and `benchmarks/README.md`.

The same reproduction also surfaced that the `electroweak` doc's Z-width row was overstated; it is corrected to `Γ_Z = 2.4223 GeV` (2.9 %).

## 4. Documentation complete

The final 10 per-shim reference pages — `qed`, `qcd`, `qft`, `neutrino`, `atomic`, `dark_sector`, `chemistry`, `topology`, `heron`, `qpu` — are written, closing the v0.3.0 "remaining documentation" item.
