## Highlights

### `nwt_substrate.isa` — the substrate Instruction Set Architecture

The single biggest change. Before v0.2.0, structural integers like `7` (K_7 vertices), `21` (K_7 edges), `8` (octonion dimension), `3` (so(7) rank / fermion generations) appeared as literals scattered across shim files. After v0.2.0, they live in `nwt_substrate.isa.constants` as named symbols and are asserted at import time to satisfy each other:

```python
assert N_EDGES_K7 == 21
assert N_EDGES_K7 == DIM_ADJ_SO7
assert 4 + 3 == N_VERTICES_K7        # K_4 + K_3 face count
assert B_QED_SM == DIM_OCTONION      # b_QED^SM = 8 substrate identity
```

Change one constant and the import refuses, because the identity chain breaks. This makes substrate-algebra integrity a property of the codebase rather than a convention.

The ISA also exposes `k7_wilson_amplitude(alpha, order=...)`, the centrepiece K_7 closed-form expression that drives `m_e / M_Pl`, Newton's G, the cosmological constant, and several other shim-spanning derivations:

```
m_e / M_Pl = (8/7) · α^(21/2) · (1 + α/7 + (21/8) α²)     [Paper 17 NNLO]
```

Every factor is a substrate primitive — `8/7 = dim(Spin(7) spinor) / dim(vector)`, `21 = K_7 edge count`, `7 = K_7 vertex count`, `21/8 = dim Adj / dim S`. There are no fitted constants in `nwt_substrate`. The ISA enforces that.

If anyone redefines the constants, the circuit assertion fires before the job hits the queue. This is what "the substrate compiles all the way to the metal" means.

## Cross-shim derivation chains

A single integer can drive multiple unrelated observables. The ISA makes the chain explicit. Examples now visible in the codebase:

- **`7`** = `N_VERTICES_K7` = number of carrier-knot crossing types = K_7 vertex count = number of Heffter faces (with `2 × 7 = 14`) = denominator of `η_B = 3α⁴/14`. Same integer, four unrelated observables.
- **`8`** = `DIM_OCTONION` = `b_QED^SM` (verified by `verify_b_qed_sm` at import) = `dim(Spin(7) spinor)` = `2 + DIM_OCTONION_imag + 1 = 9` denominator of `sin²θ_W = (2 + α) / 9`.
- **`25`** = `H_V_SO7² = q_cinq² = cinquefoil (5,2)-torus-knot crossings²` — drives `Ω_b/Ω_c = 25α + 75α²` (LO) AND `m_τ = 25 m_e / [α(1-α)²]` (Paper 17 charged-lepton chain) AND the Sirlin Δq coefficient `25/4`.
- **`21`** = `N_EDGES_K7 = dim Adj(so(7))` — drives Newton's G `α^(21/2)` Wilson amplitude AND the NNLO bracket `21/8` AND the IBM Heron 21-CZ gate count AND the QED running coefficient (when `N_C SU(3)`-active).

These aren't coincidences — they're the substrate algebra speaking through observables. The ISA is the place where the algebra is canonical.

## Breaking changes

None for end-users. Internal shim code may reference `isa.constants` symbols where it previously had inline literals, but the public API is fully backward-compatible with v0.1.x.

## Why this matters

Before the ISA, substrate-algebra integrity was a convention enforced by code review. After the ISA, it's a property the Python interpreter enforces at import time. Three things that previously could go silently wrong now refuse to load:

1. Drifting `21` in one shim while another shim still says `21` — caught by `assert N_EDGES_K7 == DIM_ADJ_SO7`.
2. Fitted parameters slipping past review — there's no longer a place for them to live; the substrate primitives are named, asserted, and exposed.
3. Cross-shim inconsistencies — every shim imports the same `isa.constants` symbols, so drift is impossible by construction.

This is what `nwt-substrate` becoming the canonical executable substrate algebra looks like.
